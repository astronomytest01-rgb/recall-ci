# Формат пака карточек Recall

Пак — один JSON-файл в `Recall/Packs/` (встраивается в приложение) или импортированный через «Файлы» на телефоне.

```json
{
  "id": "kitchen-basics",              // уникальный, kebab-case
  "title": "Основы кухни",             // короткое название пака
  "subtitle": "Техники, продукты, термины",
  "source": "my-notes",                // имя репозитория-источника
  "icon": "fork.knife",                // SF Symbol
  "version": 1,
  "topics": [
    { "id": "techniques", "title": "Техники", "icon": "flame" }
  ],
  "cards": [
    {
      "id": "techniques-001",              // уникален внутри пака, стабилен между версиями
      "topic": "techniques",
      "type": "choice",                // "choice" — выбор ответа, "flash" — карточка с оборотом
      "q": "При какой температуре закипает вода на уровне моря?",
      "options": ["100 °C", "90 °C", "110 °C", "120 °C"],
      "answer": 0,                      // индекс правильного варианта в options (приложение перемешивает)
      "explain": "Коротко, почему так и как запомнить.",
      "source": "notes/cooking.md"
    },
    {
      "id": "techniques-002",
      "topic": "techniques",
      "type": "flash",
      "q": "Что такое бланширование?",
      "back": "Ответ, 1–3 предложения.",
      "explain": "Необязательное дополнение.",
      "source": "notes/cooking.md"
    }
  ]
}
```

## Что брать в карточки

Только долговечное общее знание, которое пригодится и через год: как устроен продукт, правила и чек-листы, определения метрик и как измерять решения, психология пользователя, принципы UX вместе с аргументами, процессы.

Не брать:
- людей и роли: кто что сказал, кто решил, кто за что отвечает;
- историю: встречи, даты событий, «было → стало», релизы;
- трекеры: ключи задач, число тикетов, статусы;
- быстро устаревающие числа: «у 9 из 14 конкурентов», счётчики сканов, дневную статистику;
- идентификаторы: ключи файлов, id узлов, ссылки, домены;
- оргструктуру, кадровые новости, доступы.

Хорошая карточка формулирует правило или понятие обезличенно и объясняет, почему оно такое.

## Правила качества

- Только факты из источника. Никаких догадок; если в источнике «по словам коллеги» или «предположение», так и пишем в вопросе или объяснении.
- `choice`: 3–4 варианта, неправильные правдоподобные (из того же домена), одной длины с правильным. Не «все перечисленные». Верно/неверно — 2 варианта `["Верно", "Неверно"]`.
- `flash`: для определений, списков, «почему», процессов. Оборот короткий.
- Пропорция примерно 70 % `choice`, 30 % `flash`.
- Вопрос понятен без контекста: называй бренд, дату, человека полностью.
- `explain` — 1–2 предложения: почему так, с деталью, которая помогает запомнить.
- Язык карточек — русский; термины продукта, названия брендов и UI-тексты оставляй как в источнике.
- Без секретов: никаких паролей, токенов, логинов тестовых аккаунтов.
- JSON валидный, без комментариев.
